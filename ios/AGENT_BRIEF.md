# Brief for screen agents (Crate iOS app)

Repo: this repository (the `crate/` folder). App sources: `ios/Crate/` (Xcode 16+ synchronized folders: any .swift you add is compiled automatically; never edit `ios/Crate.xcodeproj`). Design handoff (source of truth): the design handoff in `../design/` (next to the repo; not public) — read `README.md`, `design-notes.md` (Step 6 first), `design-system.md`; screens in `Crate Update v2.dc.html` (6a–6v, wins over older files), `Crate Core Flow.dc.html` (2a–2l), `Crate App Screens.dc.html` (3a–3n), `Crate Light Mode.dc.html`. The HTML is a reference; build native SwiftUI (iOS 17 minimum, Swift 6 strict concurrency, no third-party deps). Native behaviour wins over HTML details.

What already exists (read before writing code):
- `ios/CrateKit/Sources/CrateKit` — models (LibraryFile, Track, Consensus, Vibe/VibesFile, Preset/PresetsFile, WeeklyFile, HealthFile, TaxonomyFile, TrackOverride), QueryEngine, VibeIndex, VectorIndex, Camelot, Tags, StyleShade, SigningExpiry, Spotify client.
- `ios/CrateKit/Sources/CrateUI` — tokens (`Tokens.generated.swift`, don't edit) and components in `Components/` (StyleChip, GenreSummaryChip, FamilyMiniChip, VibeChip, TagChip, TagSuggestionRow, ConfidenceLine, ConfidenceMarker, BPMText, EnergyMeter, EnergyRangeControl, RangeSlider, CamelotBadge, CamelotWheel, CoverImage, TrackRow, CompactTagLine, LikeButton, PresetPill, PresetTile, TickRing, PrimaryButton, PanelLabel, crateCard, ChipFlow …). Use them; if one is missing or needs a variant, add it in a NEW file under `CrateUI/Components/<YourArea>*.swift` — do not modify existing component files (other agents use them in parallel). Small fixes to existing components: describe them in your report instead.
- `ios/Crate/App` — `AppModel` (@Observable, environment): `snapshot` (all data files), `index` (LibraryIndex: tracks, overrides, effective tags, families with style counts, tagCounts, vibeMembers, vibeIndex, count(query), matchingIDs, tagSuggestions), `build` (BuildState → Query), `matchCount`, `sendState`, `send()`, `count(applying:)`, `editVibes`, `editOverride`, `editPresets`, `spotify` (SpotifyService), `isDemo`, `useDemoData()`, `saveGitHubToken`, `validateGitHub`, `reload`. `DebugLaunch` (`-demo`, `-tab`, `-screen <name>`). **Do not edit files in `ios/Crate/App/`** (shared). If you need more model API, add it as `extension AppModel { … }` in a file inside YOUR screens folder (e.g. `ios/Crate/Screens/Vibes/AppModel+Vibes.swift`), keeping it small and self-contained.
- Screen stubs with agreed names/signatures (other agents link to them): Build: `BuildView`, `GenrePickerView`, `KeyPickerView`; Vibes: `VibeEditorView(vibeID: String?, seedTrackID: String?)`, `VibesManagerView`, `VibeChooserView(trackID:, mode: .addSeed|.never)`; Tracks: `TrackDetailView(trackID:)`, `EditTagsView(trackID:)`, `TrackListView(title:, trackIDs:)`; Weekly/Library: `WeeklyView`, `LibraryView`, `PresetsManagerView`, `SavePresetView(presetID: String?)`, `OnboardingView`. Replace only the stubs you own; keep the type names and init signatures (you may add parameters with defaults). Present other areas' views as sheets/navigation by name.

Data in demo mode is the user's real library (1,015 tracks). Use real counts from `model.index`, never hardcoded numbers.

Build & verify (use YOUR derived-data path and simulator UDID so parallel agents don't collide):
```
cd ios && xcodebuild -project Crate.xcodeproj -scheme Crate -destination 'platform=iOS Simulator,id=<UDID>' -derivedDataPath ../.cache/DerivedData-<AREA> CODE_SIGNING_ALLOWED=NO build
xcrun simctl boot <UDID>; xcrun simctl install <UDID> ../.cache/DerivedData-<AREA>/Build/Products/Debug-iphonesimulator/Crate.app
xcrun simctl terminate <UDID> com.overmap.crate; xcrun simctl launch <UDID> com.overmap.crate -demo -tab <tab> -screen <name>
xcrun simctl ui <UDID> appearance dark|light; xcrun simctl io <UDID> screenshot ../.cache/screens/<area>-<state>-<dark|light>.png
```
Always pass the UDID (several simulators are booted). If the build fails because of another agent's half-finished file outside your area, wait a minute and retry; never edit their files. Add `-screen` hooks (DEBUG only, via `DebugLaunch.screen`) in your own views to open sheets/states directly for screenshots. Look at every screenshot and compare with the design; fix until it matches (dark and light). Accessibility: Dynamic Type (check one AX size: `xcrun simctl ui <UDID> content_size extra-extra-extra-large`), 44 pt targets, VoiceOver labels per README.

Don't commit. Report: files changed, screenshots, what's done vs. not, deviations, and any API you'd like added to shared files.
